# 霉害隔离舱污染谱系调度

有机质文物修复中心在隔离舱复检中检出活性霉菌后，系统依据**器物批次、隔离舱、托盘、转运车辆的接触时段**与**采样、消杀、清洁事件**，自动推导：

1. 新阳性波及哪些批次、排除哪些批次，以及每条传播路径的证据；
2. 判定时刻真正安全可用的舱位；
3. 全部定时决定（复检、通知、释放/召回），并在进程恢复后按事件原本时间继续。

结论一律由记录推导，不接受人工填写。

## 规则

- **阴性培养期**：阴性结果须采样满 72h（`minimum_culture_hours`）才生效，释放决定时间取 `max(报告时间, 采样+72h)`；报告晚于 168h 检验时限的结果失效。
- **舱门失效**：培养周期内 `door_opened` 使在舱批次的当前周期作废，30 分钟后下达定时复检。
- **共用资源扩展**：同一资源上时间重叠直接传播；施感批次离开后的滞留污染继续感染后来者（同清洁区域内）。
- **清洁边界**：只有步骤齐全、时长达标的 `cleaning_certified` 切断传播；仅有 `cleaning_started` 不阻断。边界只向后阻断，不洗白证明之前的暴露。
- **不可回溯**：污染只能由早向晚传播，已离场批次不会被后来的阳性追溯感染。
- **资源竞争**：舱室在舱批次数不得超过容量，托盘同一时间单承载，车辆允许重叠（其本身即传播媒介）。
- **事件时间**：决定全部按事件原本发生时刻排序；派发器持久化游标，进程崩溃恢复后不重复、不提前、不改动 `scheduled_at`。

## 数据

| 文件 | 内容 |
| --- | --- |
| `domain/contract.json` | 资源/批次/事件类型、必填字段、培养时限 |
| `domain/resources.json` | 舱室容量、托盘归属、车辆/工作台、竞争规则 |
| `domain/risks.json` | 菌种风险级别与处置动作 |
| `domain/inspection.json` | 培养时限、报告时限、舱门复检延迟 |
| `domain/protocols.json` | 各资源类型清洁规程（步骤、最短时长） |
| `examples/batches.json` `contacts.json` `events.json` | 批次档案、接触时段（含未结束的开放接触）、事件史 |

样例场景：`batch-organic-11` 9/12 18:00 确诊活性曲霉（high）。同车早班的 16 为时间重叠感染，23/31 在 2 号车仅有 `cleaning_started` 的情况下被滞留污染感染，52 经 B 舱重叠与 A 舱同住感染；40、70、80 分别被清洁证明边界或资源隔离排除。

## 使用

```bash
npm run validate   # 契约与引用关系校验
npm test           # 20 项规则测试
npm run report     # 影响集合 / 安全舱位 / 样本判定 / 定时决定报告

# 可中断恢复的派发器（状态持久化到 data/，已 gitignore）
node tools/run-scheduler.mjs --now 2026-09-13T00:00:00+08:00
node tools/run-scheduler.mjs --crash-after 3   # 模拟崩溃
node tools/run-scheduler.mjs --now ...         # 恢复后继续
node tools/run-scheduler.mjs --reset
```

## 引擎结构

- `src/time.js`：区间重叠/并集、清洁边界切割。
- `src/model.js`：装载与基础校验（字段、类型、引用、时间范围、开放接触）。
- `src/cleaning.js`：清洁证明有效性评估与传播边界。
- `src/samples.js`：采样生命周期（阳性/阴性生效/超时失效/舱门作废）。
- `src/tracer.js`：按清洁区域切片的时间感知传播（带证据链）。
- `src/capacity.js`：超配检测与安全舱位判定。
- `src/scheduler.js`：由事件史幂等推导定时决定。
- `src/runner.js`：持久化派发游标，支持进程恢复。

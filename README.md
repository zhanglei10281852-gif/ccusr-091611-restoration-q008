# 霉害隔离舱污染谱系调度

本项目把器物批次、隔离舱、托盘和转运车辆的接触记录组织成带时间范围的关系，并由采样、消杀、清洁事件推导隔离处置结论：召回范围、舱位可用性、放行合规与定时任务全部由事件推导，不读取任何人工填写的结论。清洁证明构成明确的传播边界，采样结果只有满足培养时间后才可用于释放决定。

## 数据

- `domain/contract.json` — 资源类型、批次状态、事件类型、接触必填字段与最短培养时限（72 小时）。
- `domain/resources.json` — 舱室能力与各资源容量（容量约束用于防止超配）。
- `domain/strains.json` — 菌种风险级别（高 / 中 / 低）。
- `domain/protocols.json` — 各级别清洁规程：清洁方式、是否要求清洁后阴性生效、定时复检间隔。
- `examples/events.json` — 历史事件流（接触、采样、结果、清洁、舱门开启、放行）。
- `examples/contacts.json` — 区间式接触样例（与事件对形态等价，可混用）。

## 推导规则

- **污染传播**：阳性主体自上一次认证清洁起视为污染；共用资源的接触时段与污染窗口重叠即扩展影响集合，逐跳迭代至不动点。
- **清洁边界**：传播不能越过已证明清洁完成（`cleaning_certified`）的时刻；边界之后的接触被排除并附排除原因。
- **培养时限**：阴性结果须等采样后满最短培养期才生效；生效前不得用于放行，高风险舱位清洁后亦须阴性生效才恢复可用。
- **舱门失效**：舱门在培养期内意外开启，当前培养循环失效，相关样本作废并触发重新采样通知。
- **资源竞争**：同一资源的并发接触不得超过其容量，超配分配被拒绝并报告冲突。
- **可恢复调度**：定时复检、通知与释放决定由事件时间确定性生成，触发记录写入 journal；进程恢复后重放事件日志，逾期任务仍按事件原本发生的时间补发，不重发、不漏发。

## 使用

```bash
npm test          # 契约与领域数据校验 + 单元测试
npm run report    # 生成调度报告（默认 examples/events.json，截至 2026-09-11T12:00+08:00）
node tools/report.mjs examples/events.json --at 2026-09-13T19:00:00+08:00
```

报告包含：召回清单（附推导链，回答“为何波及”）、排除说明（回答“为何排除”）、真正安全可用的舱位、放行合规、超配冲突、到期与未来任务。

## 结构

- `src/log.js` — 事件文件加载与规整（事件对 / 区间两种接触形态，进行中接触支持）。
- `src/engine.js` — 核心推导：污染谱系、培养生效、舱门失效、舱位可用性、放行合规、超配检测。
- `src/scheduler.js` — 定时任务推导与可恢复调度器（journal 持久化）。
- `src/allocate.js` — 分配前容量校验。
- `tools/validate-contract.mjs` / `tools/report.mjs` — 校验与报告入口。
